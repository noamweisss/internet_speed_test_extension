# ADR-0011: Draw the meter as an SVG gauge embedded in markdown

Status: accepted · Date: 2026-09-28 · Supersedes ADR-0006

## Context
ADR-0006 chose text bars (`▰▰▰▱▱▱`) for v1 because whether `MarkdownContent` renders images from `data:` URIs
was unverified. Since then Microsoft has documented it (Microsoft Learn, "Display markdown content in Command
Palette extensions", "Add images to markdown content"): since PowerToys 0.95, `MarkdownContent` renders `data:`
images, base64 or URL-encoded, and the PowerToys `SamplePagesExtension` markdown-images page embeds a base64 SVG
that way. Two caveats from the same source: the `--x-cmdpal-*` size hints do not apply to data URIs (the image
renders at its intrinsic size, so the SVG must carry `width`/`height`), and embedded images should stay small.
The owner runs PowerToys 0.101.

## Decision
The meter draws each speed as an inline SVG speedometer arc: a track and a progress arc, generated by
`GaugeSvg` in Core (a pure function, unit-tested for the arc geometry and invariant-culture output), embedded as a
base64 `data:image/svg+xml` URI of about 500 bytes, regenerated on every progress report (every 200 ms during a
transfer). The Unicode bar from ADR-0006 stays as the image's alt text. Colours are theme-neutral (a gray with
alpha for the track, the Windows accent blue for the progress) because an image cannot follow the host theme; the
numbers stay markdown text so they do.

## Consequences
- The first verification is the owner's next run. PowerToys 0.95 or newer is required; older versions show the
  alt text (the ADR-0006 bar).
- If it does not render, reverting is one line in `MeterMarkdown.AppendMeter`.
- No new dependency and no network: the data URI is content the extension generated, not fetched. Every
  `docs/SAFETY-CONTRACT.md` §3 answer stays "No".
