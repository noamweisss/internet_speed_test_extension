What Command Palette can draw, and why the gauge blinked

Research for plan item 5.1 · PowerToys 0.101 · 29 September 2026 · the agents' version with every citation is docs/CMDPAL-RENDERING.md

Short version. Command Palette never animates anything for an extension. Each frame is the extension replacing a value, the host reading it back over COM, waiting up to 40 ms, and rebuilding the whole markdown block on its UI thread. Images inside markdown are recreated empty and filled a moment later, and a data: image cannot take the host's size hints. That is why the arc jumped between measurements and flashed on every update. The fix is on our side: ease the value in the extension, put the moving part in its own small block, and prefer text or a fixed-size picture over a regenerated one. Details and options below.

1. The one mechanism behind every pixel

There is no drawing API. An extension hands the host data (markdown text, an Adaptive Card, an icon name, a list item) and the host draws it with its own native controls. When the data changes, the host redraws. The path for the meter view looks like this:

Three consequences follow directly. Nothing smooths between two values, so the arc moves in steps the size of the measurement interval. Every update rebuilds the whole block, so a picture inside it disappears for at least a frame. And no update can be faster than the 40 ms batch, so the host cannot show more than about 25 distinct frames a second. The technical document suggests 5 to 10 a second as the range to try; whether the eye gains anything above that is untested, since every extra frame is one more full rebuild.

4. Why the session 4 gauge looked wrong

  • Steps. The arc changed only when a measurement arrived, every 200 ms. Nothing in the host eases values.
  • Blink. Each update rebuilt the block and recreated the picture empty; it came back after decoding. Five times a second.
  • Size. A data: picture gets no size hints, is capped at 256 pixels wide, and is rasterised with the width scaled to the monitor's DPI but the height not. What you saw depends on the display scaling.
  • Small numbers. The value sat under a third-level heading, which the host renders at 12 px in normal weight, smaller than body text.
  • One big block. The heading, status, latency, both meters and the ISP line were re-parsed for every arc movement.

None of this is the arc geometry, which the unit tests cover. It is how the host works, and every point has a counter-measure.

5. What cannot work on 0.101

  • Animated SVG (SMIL or CSS): the renderer is Direct2D in static mode and drops every animation element.
  • Text inside an SVG: dropped. Numbers must be markdown text next to the picture.
  • Size hints on a data: image, and any width above 256 px for one.
  • A data: string as an icon (list rows, tiles, image block): icons want a file path, a glyph, one emoji, or a bitmap stream.
  • A percentage in a status message: the progress bar exists in the host's XAML and is permanently collapsed.
  • Colours that follow the theme inside any picture: the host never tells the extension which theme is active.
  • Two content blocks side by side: blocks only stack vertically.
  • Waiting for native graph content: the pull request is a draft with no milestone and an unanswered request for API sign-off.

6. Options for redrawing the meter, ranked

  1. Ease in the extension, render on a fixed tick. recommended first Keep measuring every 200 ms; a display timer at 100 to 200 ms moves the shown value toward the latest measurement and only sends a new string when it changed. Removes the steps whatever the drawing is.
  2. Split the page into blocks; move only one. recommended first Heading, status, latency and ISP line in a static block; the meter in its own block. The host rebuilds only the block whose text changed. Keep the same block objects and never ask the host to refetch the page.
  3. Draw the moving part as text. recommended first No picture means no blank frame. Finer bars from eighth-width block characters at a constant length; the number in a large heading or bold. Stays a pure function in Core with unit tests. Another extension (HardwareMonitor) ships its charts this way on purpose.
  4. Keep an SVG, but fix it and slow it. Numeric width and height and a viewBox on the root, width at most 256, only the supported elements, transparent background, its own block, two to four updates a second with easing. The blink per update remains; only a run on the PC shows whether it is visible.
  5. Pre-rendered frames as files with size hints. Fifty-one SVG files written once to the extension's temp folder, referenced by path with fit and height hints. Gains size control, keeps the blink, and writing files is a new capability that needs an ADR and a "Yes" in the safety questions.
  6. An image block with pre-rendered frames. The same files, shown through the image block, which swaps only the picture and probably keeps the old one until the new one is ready. Same file-write question; a zoom button appears on the image and cannot be removed.
  7. An Adaptive Card with a raw-SVG image. after 0.102 Exactly how the built-in Performance Monitor draws its charts. It flickers on 0.101, and the in-place update that fixes it is approved for 0.102. The right second step if you upgrade.
  8. Tiles or the details pane as the dashboard. Gallery tiles or the details pane with frame icons by file name (cached after the first decode) and coloured tag pills for the numbers. A different layout for you to judge, not a smaller change.

Suggested order on your PC: options 1 to 3 together first (no new capability, all unit-testable). Then option 4 in the same structure, to see whether the blink shows at two to four updates a second. Only then a file-based option, or option 7 after 0.102.

Glossary

Host
The Command Palette window in PowerToys. It draws everything; the extension only sends data.
COM hop
A call across the two processes. Setting a property costs two: the event out, the read back.
40 ms batch
The host waits 40 ms after a change and applies everything that arrived, once.
Markdown block
One MarkdownContent on a content page; each is rebuilt on its own.
Blank frame
The moment after a rebuild when a picture exists but has not been decoded yet.
data: image
A picture embedded in the text itself, base64-encoded. Works, but takes no size hints.
Size hints
--x-cmdpal-fit, -width, -height: query parameters that only file: and web URLs accept.
Direct2D SVG
The Windows renderer for SVG pictures: shapes, paths, gradients; no text, no styles, no animation.
Adaptive Card
A JSON layout (text, columns, images, inputs) the host renders with Microsoft's card library.
Image block
ImageContent, since 0.99: one picture with a maximum size and a zoom button.
Easing
Moving the shown value a little every tick toward the real one, instead of jumping.
